# Техническое задание: Библиотека умных указателей на C++

## 1. Базовое описание системы
Система представляет собой заголовочную библиотеку (`SmartPtrs.h`) для автоматического управления динамической памятью (RAII) в языке C++ без использования контейнеров STL. Библиотека реализует два механизма владения ресурсами в куче (Heap): исключительное владение с глубоким копированием (`UniqPtr`) и разделяемое владение с подсчётом ссылок (`ShrdPtr`), включая поддержку динамических массивов.

Дополнительно в систему входят модуль нагрузочного тестирования (`Benchmark.h`) для сравнения производительности с сырыми указателями и STL, а также модуль модульного тестирования (`tests.cpp` на базе GoogleTest) для верификации отсутствия утечек памяти.

---

## 2. Сущности системы

### Ядро библиотеки (`SmartPtrs.h`)
1. **`UniqPtr<T>`** — шаблонный класс умного указателя с исключительным владением одиночным объектом типа `T` в динамической памяти.
2. **`UniqPtr<T[]>`** — частичная специализация шаблона `UniqPtr` для владения динамическими массивами. Хранит указатель на начало массива и количество элементов (`count`).
3. **`ShrdPtr<T>`** — шаблонный класс умного указателя с разделяемым владением одиночным объектом типа `T`. Хранит указатель на данные и указатель на динамический счётчик ссылок (`ref_count`).
4. **`ShrdPtr<T[]>`** — частичная специализация шаблона `ShrdPtr` для разделяемого владения динамическими массивами.

### Модули верификации и оценки
5. **`Timer` и функции бенчмарка (`Benchmark.h`)** — подсистема замера времени выполнения операций выделения, доступа и освобождения памяти (в миллисекундах) с выводом сводной таблицы в консоль.
6. **`Tracker` и `DerivedTracker` (`tests.cpp`)** — вспомогательные классы-наблюдатели со статическим счётчиком живых экземпляров (`alive`) для детерминированной проверки корректности вызова конструкторов и деструкторов в тестах GoogleTest.

## 3. Связи между сущностями и их смысл

* **`UniqPtr<T>` $\rightarrow$ Объект `T` в куче (Композиция / Исключительное владение 1:1):**
  Указатель полностью управляет жизненным циклом объекта. При копировании `UniqPtr` создаётся независимая глубокая копия объекта `T`, поэтому два `UniqPtr` никогда не владеют одним адресом. При разрушении указателя объект гарантированно удаляется через `delete`.
* **`UniqPtr<T[]>` $\rightarrow$ Массив `T[]` в куче (Композиция / Владение массивом):**
  Аналогично `UniqPtr<T>`, но освобождение памяти выполняется через `delete[]`, а для глубокого копирования используется хранимый размер `count`.
* **`ShrdPtr<T>` $\leftrightarrow$ Счётчик ссылок `ref_count` (Ассоциация / Разделяемое владение N:1):**
  Несколько экземпляров `ShrdPtr` ссылаются на один и тот же адрес объекта `T` и один и тот же блок счётчика `ref_count` в куче. Счётчик отслеживает число активных владельцев. Объект `T` и сам счётчик удаляются только при обнулении счётчика последним владельцем.
* **`ShrdPtr<Derived>` $\rightarrow$ `ShrdPtr<Base>` и `UniqPtr<Derived>` $\rightarrow$ `UniqPtr<Base>` (Подтипизация / Полиморфное преобразование):**
  Реализована через шаблонные конструкторы преобразования (и `friend`-объявление в `ShrdPtr`). Позволяет безопасно преобразовывать умный указатель на производный класс к умному указателю на базовый класс, сохраняя корректный подсчёт ссылок (для `ShrdPtr`) или выполняя копирование (для `UniqPtr`).
* **`Benchmark` / `SmartPtrTests` $\rightarrow$ `SmartPtrs.h` (Зависимость):**
  Тестовые модули инстанцируют шаблоны умных указателей для проверки корректности работы с памятью и замера накладных расходов.

## 4. Функциональные требования

1. **Автоматическое управление памятью (RAII):**
    * Выделенная память должна автоматически освобождаться при выходе умного указателя из области видимости (`delete` для одиночных объектов, `delete[]` для массивов).
2. **Семантика владения и Правило пяти:**
    * `UniqPtr<T>` и `UniqPtr<T[]>`: поддержка глубокого копирования (конструктор копирования, оператор присваивания с защитой от самоприсваивания) и семантики перемещения (`move`-конструктор и `move`-присваивание с обнулением источника).
    * `ShrdPtr<T>` и `ShrdPtr<T[]>`: разделяемое владение при копировании (инкремент счётчика), передача владения без изменения счётчика при перемещении, декремент и очистка памяти при разрушении или перезаписи.
3. **Интерфейс доступа и управления:**
    * Для одиночных объектов: операторы разыменования `*`, доступа к членам `->`, метод `Get()`.
    * Для массивов: оператор индексации `[]`, метод `Get()`, метод `Size()` (для `UniqPtr<T[]>`).
    * Общие методы управления: `Reset()` (смена/сброс управляемого объекта), `Release()` (отказ от владения без удаления в `UniqPtr`), `use_count()` (текущее число ссылок в `ShrdPtr`), явное приведение к `bool` (`explicit operator bool()`).
4. **Поддержка подтипизации:**
    * Возможность конструирования указателя на базовый тип из указателя на производный тип (с проверкой совместимости типов на этапе компиляции).
5. **Тестирование и бенчмаркинг:**
    * Автоматическая проверка отсутствия утечек памяти через GoogleTest для всех сценариев (создание, копирование, перемещение, самоприсваивание, `Reset`/`Release`, массивы, наследование).
    * Сравнительный замер времени работы (сырые указатели vs кастомные указатели vs STL) на объёмах от $10^2$ до $10^7$ объектов с табличным выводом в консоль.

---

## 5. Нефункциональные требования

1. **Производительность (Zero-cost abstraction для `UniqPtr`):**
    * В режиме сборки `Release` (`-O2`/`-O3`) накладные расходы `UniqPtr` по времени выполнения должны быть сопоставимы с сырыми указателями (`new`/`delete`) и `std::unique_ptr`.
    * Отсутствие накладных расходов в рантайме на различение одиночных объектов и массивов (достигается за счёт частичной специализации шаблонов на этапе компиляции).
2. **Безопасность памяти и исключений:**
    * Отсутствие утечек памяти (Memory Leaks) и двойного освобождения (Double Free).
    * Операции перемещения, освобождения (`Release`), `Get()` и проверки на пустоту помечены как `noexcept`.
    * Защита от неявных преобразований сырых указателей и приведения к `bool` с помощью `explicit`.
3. **Независимость от STL:**
    * Ядро библиотеки (`SmartPtrs.h`) не использует контейнеры и умные указатели стандартной библиотеки (STL допускается только в `Benchmark.h` для сравнения).
4. **Модульность и кроссплатформенность сборки:**
    * Код разделён на независимые модули (`SmartPtrs.h`, `Benchmark.h`, `main.cpp`, `tests.cpp`), сборка и подключение зависимостей (GoogleTest) автоматизированы через `CMakeLists.txt`.
