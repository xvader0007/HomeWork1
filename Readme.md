# ТЗ: Лабораторная работа №1 «Умные указатели»

## 1. Описание системы

Библиотека на C++ для автоматического управления динамической памятью (RAII) без использования умных указателей STL[cite: 2]. Решает проблемы утечек памяти, двойного удаления, висячих ссылок и неверного удаления массивов[cite: 2].

Реализуются два вида владения (для одиночных объектов и для массивов)[cite: 2]:

* **Единоличное владение** (аналог `std::unique_ptr`) — у объекта ровно один владелец; владение можно передать, но нельзя скопировать[cite: 2].
* **Разделяемое владение** (аналог `std::shared_ptr`) — у объекта несколько равноправных владельцев; счётчик хранится децентрализованно (вариант 2, без отдельного хранилища объектов), объект удаляется последним владельцем[cite: 2].

Для проверки и оценки решения в систему также входят динамический массив на умных указателях, функциональные тесты (GoogleTest), нагрузочный стенд с выводом таблиц/CSV, построение графиков (matplotlib) и проверка памяти (valgrind, ASan/UBSan)[cite: 2].

## 2. Сущности и связи

### Сущности

| Сущность | Описание |
| :--- | :--- |
| **Объект / Массив объектов** | Данные в динамической памяти; массив удаляется отдельным способом и поддерживает доступ по индексу[cite: 2]. |
| **Единоличный владелец** | Указатель с исключительным владением (1:1); хранит только адрес объекта[cite: 2]. |
| **Разделяемый владелец** | Указатель с совместным владением (N:1); хранит адрес объекта и адрес общего счётчика[cite: 2]. |
| **Число владельцев (счётчик)** | Неатомарное число в динамической памяти; при обнулении удаляются объект и сам счётчик[cite: 2]. |
| **Тип и подтип** | Иерархия наследования: указатель на подтип можно использовать как указатель на базовый тип[cite: 2]. |
| **Коллекция (контейнер)** | Динамический массив на основе единоличного указателя, способный хранить в том числе разделяемые указатели[cite: 2]. |
| **Нагрузочный стенд и визуализация** | Модуль замера времени и памяти (Raw vs свои указатели vs STL) с экспортом в консоль/CSV и графиками PNG[cite: 2]. |
| **Проверка памяти и тесты** | Модульные тесты (GoogleTest) и прогон под valgrind, ASan/UBSan + контрольный пример с намеренной утечкой[cite: 2]. |

### Связи между сущностями

```text
Единоличный владелец ──(владеет 1:1 / передаёт)──▶ Объект / Массив
         │ (превращается в разделяемое)
         ▼
Разделяемые владельцы ─(владеют N:1)─────────────▶ Объект / Массив
         │                                               ▲
         └──(делят общий)──▶ Счётчик ──(при 0: delete)───┘

Коллекция ──(содержит 0..n)──▶ Элементы (в т.ч. разделяемые указатели)
Подтип    ──(является)───────▶ Тип (только для одиночных объектов)
```

* **Владение (1:1 и N:1):** владелец обязан удалить ресурс при завершении его использования[cite: 2]. Единоличное владение можно перевести в разделяемое, но не наоборот[cite: 2].
* **Подтипизация:** указатель на подтип приводится к указателю на базовый тип; для несвязанных типов и массивов преобразование запрещено[cite: 2].
* **Изоляция библиотеки:** контейнер, тесты и стенд зависят от библиотеки указателей, но сама библиотека ни от чего, кроме языка, не зависит[cite: 2].

## 3. Функциональные требования

### Единоличный указатель (объект и массив)

* Создание пустого указателя, от сырого адреса или через функцию-фабрику[cite: 2].
* Доступ через `*`, `->` (объект) или `[]` (массив), получение адреса, проверка на пустоту[cite: 2]. Обращение через пустой указатель бросает исключение[cite: 2].
* Передача владения (перемещение) с обнулением источника; копирование запрещено на этапе компиляции[cite: 2].
* Управление: отказ от владения без удаления, замена/сброс объекта (с защитой от замены тем же адресом и самоприсваивания), обмен (`swap`)[cite: 2].
* Автоматическое удаление (`delete` / `delete[]`) при уничтожении[cite: 2].

### Разделяемый указатель (объект и массив)

* Создание пустого (счётчик не выделяется), от адреса, через фабрику или из единоличного указателя[cite: 2].
* Копирование (счётчик +1 за O(1)), перемещение (счётчик не меняется), присваивание (с защитой от самоприсваивания и присваивания между владельцами одного объекта)[cite: 2].
* Получение числа владельцев, доступ к данным, проверка на пустоту, сравнение адресов, сброс, замена, обмен[cite: 2].
* Автоматическое удаление объекта и счётчика последним владельцем; при ошибке выделения памяти под счётчик утечки не происходит[cite: 2].

### Подтипизация и контейнер

* **Подтипизация:** преобразование `Подтип` → `Тип` (с общим счётчиком для разделяемых); запрет на этапе компиляции для `Тип` → `Подтип`, несвязанных типов и массивов[cite: 2].
* **Контейнер (динамический массив):** создание, чтение/запись по индексу за O(1) с проверкой границ (исключение при выходе), добавление в конец с удвоением ёмкости (амортизированно O(1)), изменение размера, глубокое копирование и перемещение[cite: 2].

### Тестирование, стенд и проверка памяти

* **Тесты:** автоматическая проверка всех сценариев и равенства числа созданных и удалённых объектов после каждого теста[cite: 2].
* **Нагрузочный стенд (CLI):** замеры времени (медиана по прогонам, с защитой от оптимизации компилятора) и памяти для $N$ от $1$ до $10^8$, вывод таблиц в консоль и CSV, построение графиков[cite: 2].
* **Проверка памяти:** прогон тестов и стенда под valgrind, ASan и UBSan, плюс обязательное обнаружение намеренной утечки в контрольном примере[cite: 2].

## 4. Нефункциональные требования и ограничения

* **Производительность:** единоличный указатель не медленнее ручного управления; разделяемый быстрее `std::shared_ptr` за счёт неатомарного счётчика[cite: 2].
* **Память:** единоличный указатель равен размеру обычного указателя; разделяемый — не больше стандартного[cite: 2].
* **Надёжность и стиль:** отсутствие утечек, двойного удаления и UB; стандарт C++17, сборка через CMake (Windows/Linux) без предупреждений, стиль по правилам Голуба, консольный интерфейс[cite: 2].
* **Ограничения:** библиотека без умных указателей STL; `weak_ptr` и кастомные удалители не реализуются; разделяемый указатель однопоточный; циклические ссылки ведут к утечке; нельзя передавать один сырой адрес двум независимым разделяемым указателям; полиморфное удаление требует виртуального деструктора базового класса[cite: 2].
