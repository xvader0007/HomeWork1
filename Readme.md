# ТЗ: Лабораторная работа №1 «Умные указатели»

## 1. Описание системы
Заголовочная библиотека на C++ (`SmartPtrs.h`) для автоматического управления динамической памятью (RAII) без использования контейнеров и умных указателей STL. Реализует два вида владения ресурсами в куче (для одиночных объектов и массивов):
- **Исключительное (`UniqPtr`)** — 1 владелец на объект; при копировании создаётся глубокая копия данных, при перемещении адрес передаётся без копирования.
- **Разделяемое (`ShrdPtr`)** — $N$ владельцев на объект; децентрализованный счётчик ссылок в куче, удаление объекта последним владельцем.

В систему также входят модуль модульного тестирования (`tests.cpp`, GoogleTest) для верификации отсутствия утечек и консольный стенд (`Benchmark.h`, `main.cpp`) для сравнения производительности с сырыми указателями и STL.

---

## 2. Сущности и связи

### Сущности
| Сущность | Роль в системе |
|---|---|
| **`UniqPtr<T>` / `UniqPtr<T[]>`** | Исключительный владелец объекта (`T*`) или массива (`T*` + `count`). |
| **`ShrdPtr<T>` / `ShrdPtr<T[]>`** | Разделяемый владелец (`T*` + `ref_count`). |
| **Счётчик ссылок (`ref_count`)** | Динамическая переменная в куче, хранящая число активных `ShrdPtr` на один объект. |
| **Объект / Массив в куче** | Управляемый ресурс (`new` / `new[]`), время жизни которого привязано к владельцу. |
| **`Tracker` / `DerivedTracker`** | Тестовые сущности со статическим счётчиком `alive` для фиксации утечек и проверки наследования. |
| **Нагрузочный стенд (`Benchmark`)** | Исполняет сценарии нагрузки для Raw, кастомных указателей и STL, замеряет время (мс). |

### Связи и их смысл
```
UniqPtr<T / T[]> ──(владеет 1:1, delete / delete[])──▶ Объект / Массив
       │ (move: передача адреса; copy: глубокое копирование)

ShrdPtr<T / T[]> ──(владеют N:1)─────────────────────▶ Объект / Массив
       │                                                      ▲
       └──(делят общий)──▶ ref_count ──(при 0: удаление)──────┘

Ptr<Derived> ──(подтипизация, только для одиночных)──▶ Ptr<Base>

SmartPtrTests (GTest + Tracker) ──(проверяет утечки)──▶ SmartPtrs.h
Benchmark (CLI + STL эталон)    ──(замеряет время)────▶ SmartPtrs.h
```

- **Владение (1:1 и N:1):** гарантирует вызов `delete` (для `T`) или `delete[]` (для `T[]`) при потере последнего владельца.
- **Подтипизация (`Derived` → `Base`):** разрешена через шаблонные конструкторы преобразования (с `friend` в `ShrdPtr`); для массивов запрещена из-за риска нарушения арифметики указателей (`sizeof(Base) != sizeof(Derived)`).
- **Изоляция ядра:** `SmartPtrs.h` не зависит от тестов, бенчмарка и STL.

## 3. Функциональные требования

### `UniqPtr<T>` и `UniqPtr<T[]>`
- **Жизненный цикл (Правило пяти):** явный конструктор от `T*` (и `count` для массива), глубокое копирование (конструктор и присваивание с защитой от самоприсваивания), перемещение за $O(1)$ с обнулением источника, деструктор (`delete` / `delete[]`).
- **Доступ и управление:** `*`, `->` (для `T`); `[]`, `size()` (для `T[]`); `get()`, `explicit operator bool()`, `release()` (отдать адрес без удаления), `reset()` (заменить/сбросить объект с защитой от передачи того же адреса).

### `ShrdPtr<T>` и `ShrdPtr<T[]>`
- **Жизненный цикл (Правило пяти):** явный конструктор (для `nullptr` счётчик не выделяется), копирование с инкрементом счётчика за $O(1)$, перемещение без изменения счётчика за $O(1)$, присваивание с защитой от самоприсваивания, деструктор с декрементом и очисткой данных и счётчика при нуле.
- **Доступ и управление:** `*`, `->` (для `T`); `[]` (для `T[]`); `get()`, `use_count()`, `explicit operator bool()`, `reset()`.

### Подтипизация, тесты и бенчмарк
- **Подтипизация:** преобразование `Ptr<Derived>` → `Ptr<Base>` (в `ShrdPtr` с сохранением общего `ref_count`); запрет на этапе компиляции для несвязанных типов, `Base` → `Derived` и массивов.
- **Тестирование (`tests.cpp`):** автоматическая проверка всех операций и инварианта `Tracker::alive == 0` после выхода указателей из области видимости.
- **Бенчмарк (`Benchmark.h`):** замер времени создания, доступа/копирования и удаления для $N \in [10^2; 10^7]$ объектов (Raw vs My vs STL) с табличным выводом в консоль.

## 4. Нефункциональные требования и ограничения

| Критерий | Требование / Ограничение |
|---|---|
| **Производительность** | В `Release` (`-O2`/`-O3`) `UniqPtr` работает без накладных расходов относительно `new`/`delete` (zero-cost abstraction); `ShrdPtr` быстрее `std::shared_ptr` в одном потоке за счёт неатомарного счётчика. |
| **Память** | `UniqPtr<T>` равен размеру `T*`; разделение `T` и `T[]` выполнено через частичную специализацию шаблонов без флагов в рантайме. |
| **Безопасность** | Отсутствие утечек и двойного удаления; `move`-операции, `get()`, `release()`, `use_count()` и `operator bool()` помечены `noexcept`; конструкторы от `T*` помечены `explicit`. |
| **Зависимости и сборка** | Ядро без STL; `weak_ptr` не реализуется; сборка через CMake (GCC/MinGW), консольный интерфейс (CLI). |
| **Ограничения контракта** | `ShrdPtr` не потокобезопасен; циклические ссылки ведут к утечке; нельзя передавать один сырой адрес двум независимым умным указателям; полиморфное удаление требует `virtual ~Base()`. |
