# ТЗ: Лабораторная работа №1 «Умные указатели»

## 1. Описание системы

Библиотека на C++ (`SmartPtrs.h`) для автоматического управления динамической памятью (RAII) без использования умных указателей STL. Решает проблему утечек памяти и двойного удаления.

Реализованы два типа умных указателей (для одиночных объектов и для массивов):

* **`UniqPtr`** — исключительное владение: у каждого объекта в куче ровно один владелец; копирование создаёт независимую копию объекта, перемещение передаёт адрес.
* **`ShrdPtr`** — разделяемое владение: одним объектом могут владеть несколько указателей; объект удаляется последним владельцем.

В проект также входят модульные тесты на утечки памяти (`tests.cpp` на GoogleTest) и консольный тест скорости (`Benchmark.h`, `main.cpp`) для сравнения с сырыми указателями и STL.

## 2. Сущности и связи

### Сущности

| Сущность | Описание |
| :--- | :--- |
| **Объект / Массив в куче** | Данные, выделенные через `new` или `new[]`. |
| **`UniqPtr<T>` и `UniqPtr<T[]>`** | Умный указатель с исключительным владением (для массива дополнительно хранит размер `count`). |
| **`ShrdPtr<T>` и `ShrdPtr<T[]>`** | Умный указатель с разделяемым владением. |
| **`ControlBlock`** | Блок управления в куче, хранящий потокобезопасный счётчик владельцев (`std::atomic<int>`). |
| **`Tracker` и `DerivedTracker`** | Тестовые классы со счётчиком живых объектов (`alive`) для проверки утечек памяти и наследования. |
| **`Benchmark` и `Timer`** | Модуль замера времени работы (в миллисекундах) и вывода таблицы в консоль. |

### Связи между сущностями

```text
UniqPtr<T / T[]> ──(владеет 1:1)───────────────────▶ Объект / Массив
ShrdPtr<T / T[]> ──(владеют N:1)───────────────────▶ Объект / Массив
       │                                                   ▲
       └──(делят общий)──▶ ControlBlock ──(при 0: delete)──┘

Ptr<Derived> ──(подтипизация, только для T)────────▶ Ptr<Base>
```

* **Владение 1:1 (`UniqPtr` → ресурс):** указатель сам удаляет ресурс (`delete` или `delete[]`) при выходе из области видимости.
* **Владение N:1 (`ShrdPtr` → ресурс и `ControlBlock`):** все копии `ShrdPtr` ссылаются на один `ControlBlock`. При обнулении счётчика последний владелец удаляет и ресурс, и `ControlBlock`.
* **Подтипизация (`Derived` → `Base`):** позволяет преобразовать указатель на наследника в указатель на базовый класс. Для массивов запрещена, чтобы не сломать индексацию из-за разного размера элементов.
* **Проверка и замеры:** `tests.cpp` и `Benchmark.h` используют `SmartPtrs.h`, но сама библиотека от них не зависит.

## 3. Функциональные требования

### `UniqPtr<T>` и `UniqPtr<T[]>`

* Создание пустого указателя или от сырого адреса (для массива — с указанием размера).
* Глубокое копирование и присваивание (с защитой от самоприсваивания `p = p`).
* Перемещение: передача владения без копирования, исходный указатель обнуляется.
* Доступ к данным: `*`, `->` (для объекта), `[]` и `Size()` (для массива), `Get()`, проверка на пустоту (`bool`).
* Управление: `Release()` (отдать сырой указатель без удаления) и `Reset()` (заменить или сбросить объект).
* Автоматическое удаление (`delete` / `delete[]`) в деструкторе.

### `ShrdPtr<T>` и `ShrdPtr<T[]>`

* Создание пустого указателя (без выделения `ControlBlock`) или от сырого адреса (счётчик равен 1).
* Копирование и присваивание с увеличением счётчика в `ControlBlock` (с защитой от самоприсваивания).
* Перемещение без изменения счётчика.
* Доступ и управление: `*`, `->` (для объекта), `[]` (для массива), `get()`, `Use_count()`, проверка на пустоту (`bool`), `Reset()`.
* Автоматическое уменьшение счётчика и удаление ресурса вместе с `ControlBlock` последним владельцем.

### Подтипизация, тесты и бенчмарк

* Преобразование `UniqPtr<Derived>` → `UniqPtr<Base>` и `ShrdPtr<Derived>` → `ShrdPtr<Base>`.
* Автоматические тесты в GoogleTest: проверка всех операций и контроль отсутствия утечек (`Tracker::alive == 0`).
* Сравнение скорости работы (Raw vs My vs STL) на объёмах от 10² до 10⁷ объектов с выводом таблицы в консоль.

## 4. Нефункциональные требования и ограничения

* **Отсутствие утечек памяти:** каждый `new` / `new[]` гарантированно закрывается парным `delete` / `delete[]`.
* **Безопасность:** операции перемещения, геттеры и очистка помечены `noexcept`; конструкторы от сырого указателя и оператор `bool` помечены `explicit` (защита от случайных неявных преобразований).
* **Потокобезопасность счётчика:** в `ControlBlock` используется `std::atomic<int>` (`fetch_add` / `fetch_sub`) вместо обычного `++` / `--`.
* **Эффективность:** разделение на одиночные объекты и массивы выполнено через частичную специализацию шаблонов (без лишних флагов и проверок во время работы). В режиме `Release` `UniqPtr` работает на уровне сырых указателей.
* **Независимость и сборка:** ядро `SmartPtrs.h` не использует контейнеры и умные указатели STL; сборка проекта и тестов автоматизирована через `CMakeLists.txt`; интерфейс — консольный.
* **Ограничения:** `weak_ptr` не реализуется (циклические ссылки не разрываются); нельзя передавать один и тот же сырой адрес в два разных умных указателя; для удаления наследника через базовый указатель у базового класса должен быть виртуальный деструктор.
